## 2. 오답 노트 관리 및 유사 오답 피드백 규칙
- **타 트랙/상관없는 일차 파일 수정 절대 금지 규칙**: 현재 진행 중인 특정 트랙(예: SQL 풀이 진행 중)에서는 관련 없는 다른 트랙(Python)이나 다른 일차의 파일을 절대로 수정하거나 건드리지 않습니다. 오직 현재 풀어보고 있는 특정 언어 및 해당 일차 파일만 최소한으로 업데이트합니다.
- **사전 오답 작성 절대 금지 규칙**: 신규 문제 및 일차 폴더를 세팅할 때 오답노트(`N일차_오답노트.md`)에 예상 오답, 힌트, 풀이 팁을 절대로 미리 작성하지 않습니다. 오답노트는 오직 사용자가 직접 문제를 풀어본 뒤 틀린 부분(오타, 문법 에러, 논리 오류 등)이나 모르는 부분을 질문했을 때만 해당 내용에 한하여 수록합니다.
- **실수 및 약점 누적 기록 규칙**: 일차별 문제를 풀면서 사용자가 틀렸거나 피드백을 통해 수정했던 부분(문법 에러, 잘못된 접근 방식, 오타 등)을 해당 일차 폴더 내 `N일차_오답노트.md` 및 `README.md` 약점 노트 섹션에 요약 정리하여 즉시 누적 기록합니다.
- **Notion 오답노트 동기화 규칙**: 오답노트 및 약점 분석 노트를 [프로그래머스 오답노트 노션 데이터베이스](https://app.notion.com/p/3ad02c86460880fe98bac2d515cb472b?v=c5002c86460883c8991508baedc2c0a8) (Database ID: `3ad02c86-4608-80fe-98ba-c2d515cb472b`)에 동기화하여 수록합니다.
- **Python / SQL 분리 태깅 규칙**: 노션 데이터베이스 등록 시 Python 문제(`사용 도구/언어: Python`, `학습 분야: 파이썬`)와 SQL 문제(`사용 도구/언어: SQL`, `학습 분야: 데이터 분석`)를 엄격히 분리 태깅하여 필터 및 뷰로 각각 독립하여 볼 수 있도록 수록합니다.
- **유사 유형 재발 시 과거 문제 언급 규칙**: 이후 유사한 문제나 패턴에서 사용자가 동일/유사한 실수가 범해질 경우, 이전에 해당 실수가 발생했던 특정 문제(예: "SQL 7일차 1번 문제에서 발생했던 WHERE절 집계함수 오류와 동일한 패턴입니다")를 명시적으로 언급하며 교정합니다.

## 4. 주피터 노트북(.ipynb) 세팅 및 디렉토리 구조 규칙
- **일차별 디렉토리 생성 규칙**:
  - Python: `python/N일차/N일차.ipynb` 및 `python/N일차/N일차_오답노트.md`
  - SQL: `sql/N일차/N일차.ipynb` 및 `sql/N일차/N일차_오답노트.md`
- **기존 작성 코드 보존 규칙**: 주피터 노트북(.ipynb)의 지문이나 표 내용을 수정할 때, 사용자가 이전에 작성한 코드 셀 내용을 반드시 보존하고 초기화하지 않습니다.
- **사용자 코드 셀 임의 수정 절대 금지 규칙**: 사용자가 작성한 코드 셀은 피드백이나 풀이 리뷰를 제공하더라도 절대로 직접 수정하거나 정답 코드로 덮어씌우지 않습니다. 교정 및 정답 코드는 오직 답변 텍스트로만 제공하며, 주피터 노트북(.ipynb) 내 코드 수정은 완전히 사용자가 직접 수행할 수 있도록 기존 코드를 100% 보존합니다.
- **정답 및 뼈대 코드 최소화 규칙 (학습 주도성 보장)**:
  - 신규 문제를 세팅할 때 스타터 코드는 오직 프로그래머스 웹사이트가 기본 제공하는 수준인 **기본 함수 껍데기(`def solution(...)`)와 기본 리턴문(`return answer`)**만 제공합니다. (SQL의 경우 `SELECT` 구문 하나만 제공)
  - 내부 변수 선언, 루프 조건문 등의 정답 코드는 절대 미리 작성해두지 않고 완전히 사용자가 빈 화면에서 짤 수 있도록 비워둡니다.
- **SQL 예시 테이블 및 결과 수록**:
  - SQL 문제를 제공하거나 노트북 노트를 세팅할 때, **지문 내에 예시로 제공되는 테이블 구조(컬럼 및 샘플 데이터)와 기대되는 최종 출력 결과 테이블**을 마크다운 표(Table) 형태로 반드시 수록합니다.
- **입출력 예 설명 수록**:
  - 문제를 추천하거나 노트북 노트를 생성할 때, 단순 입출력 예시 값 외에도 **입출력 예시에 대한 상세한 작동 흐름 설명**을 누락 없이 함께 수록합니다.
- **날짜 기반 N일차 생성 규칙**:
  - `N일차` 폴더는 실제 날짜(자정 00:00 KST) 기준으로 **하루에 1개만 사용**합니다.
  - 동일한 날짜 내에서 추가 문제 요청 시 새 일차 폴더(`N+1일차`)를 생성하지 않고, **당일 전용 폴더(`N일차`) 내부 파일에 추가 문제(문제 2, 문제 3...)를 계속 이어붙여 세팅**합니다.
  - 자정이 지나서 다음날이 되었을 때만 다음 일차 폴더(`N+1일차`)를 생성합니다.
- **Jupyter Notebook (.ipynb) 무결성 및 문법 검사**:
  - `N일차.ipynb` 주피터 노트북 파일 생성 및 수정 시 반드시 JSON 규격을 엄격히 준수하여 에디터 파싱 오류가 발생하지 않도록 사전 유효성 검사를 거칩니다.

## 6. 사용자 오답 및 약점 분석 노트 (지속 업데이트)

### Python 알고리즘
- **Python 9일차 2번 (K번째수)**:
  - `list.append(a, b)`처럼 2개 이상의 인자를 전달하여 `TypeError` 발생 -> 구하고자 하는 단일 값만 `append()`할 것.
  - 1-based 인덱싱과 0-based 인덱싱 차이 (`i`번째 -> `i-1` 인덱스) 유의.
- **Python 9일차 3번 (가장 큰 수)**:
  - 문자열 비교 시 자릿수가 다를 경우 단순 내림차순 정렬하면 오류 발생 (예: `'3'`과 `'30'`) -> 문자열 3회 반복(`x * 3`) 비교 정렬 패턴 활용.
  - `list.sort()`는 제자리 정렬로 `None`을 반환하므로 `"".join(list.sort())` 형태로 직접 사용 불가.
- **Python 10일차 1번 (큰 수 만들기)**:
  - `range(str_var)` 사용 시 `TypeError` 발생 -> `for num in number:` 문자열 direct 순회 활용.
  - `stack[0]`은 바닥 원소 -> 스택 상단 비교 시 `stack[-1]` 활용.
  - 다중 연속 제거 시 `if` 대신 `while stack and stack[-1] < num and k > 0:` 활용.
  - 내림차순 등으로 `k`가 남아있을 경우 `stack[:-k]` 슬라이싱 예외 처리.
- **Python 10일차 2번 (같은 숫자는 싫어)**:
  - `set()` 적용 시 연속 중복이 아닌 전체 중복 제거 및 순서 파괴 발생 -> `if not answer or answer[-1] != i` 단락 평가 `or` 조건문 활용.
- **Python 10일차 3번 (기능개발)**:
  - 날짜 계산 시 `round()` 반올림 사용 오류 -> `math.ceil()` 올림 활용.
  - `max_day` 기준일 및 `count` 변수를 활용한 그룹화 배포 조건 작성.

### SQL
- **SQL 7일차 1번 (오랜 기간 보호한 동물(2))**:
  - **`WHERE` 절 집계 함수 사용 불가**: `WHERE` 절에는 `MAX()` 같은 집계 함수를 쓸 수 없으며, 상위 N개 추출 시 `ORDER BY + LIMIT` 조합 활용할 것.
  - **함수명 및 오타**: MySQL 날짜 일수 차이는 `DATE_DIFF`가 아닌 **`DATEDIFF(종료일, 시작일)`** 사용.
  - **컬럼명 및 모호성**: 테이블의 이름 컬럼은 `ANIMAL_NAME`이 아니라 **`NAME`**이며, 다중 테이블 조인 시 `A.ANIMAL_ID` 처럼 테이블 별칭 필수 명시.
  - **정렬 방향**: "가장 길었던" 조건은 오름차순(`ASC`)이 아닌 **내림차순(`DESC`)** 적용.
- **SQL 7일차 2번 (식품분류별 가장 높은 가격의 식품 정보 조회하기)**:
  - **`GROUP BY` 기준 오설정**: `PRODUCT_ID`로 그룹화 시 개별 행이 출력됨 -> `CATEGORY`로 그룹화할 것.
  - **그룹화 시 타 컬럼 불일치**: `GROUP BY CATEGORY`를 한 뒤 `PRODUCT_NAME`을 그냥 뽑으면 최고가 상품명이 아닌 임의의 상품명이 반환됨 -> `WHERE (CATEGORY, PRICE) IN (서브쿼리)` 패턴 필수 적용.
  - **문자열 조건 오타**: `IN ("'과자', '국'...")` 처럼 전체를 따옴표로 묶으면 1개의 단어로 인식됨 -> `IN ('과자', '국', '김치', '식용유')` 개별 문자열 분리할 것.
- **SQL 7일차 3번 (취소되지 않은 진료 예약 조회하기)**:
  - **다중 테이블 조인 시 컬럼 모호성(Ambiguous)**: `PATIENT`, `APPOINTMENT`, `DOCTOR` 3개 테이블 조인 시 `PT_NO`, `MCDP_CD` 등 공통 컬럼은 `B.PT_NO`, `C.MCDP_CD` 처럼 테이블 별칭 필수 명시.
