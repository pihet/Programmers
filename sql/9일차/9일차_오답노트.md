## 2. 실수 및 약점 분석 노트

### [SQL 9일차 1번 - 헤비 유저가 소유한 장소]
- **`WHERE` 절 `IN` 연산자 누락**: `WHERE (서브쿼리)` 형태로 연산자 없이 서브쿼리만 괄호로 감싸 구문 오류(Syntax Error) 발생 -> 메인 쿼리의 `HOST_ID`와 비교하도록 `WHERE HOST_ID IN (서브쿼리)` 연산자 필수 작성.
- **서브쿼리 `SELECT` 컬럼 및 오타 문제**:
  - `HOST_ID2`라는 존재하지 않는 컬럼 오타 작성.
  - 서브쿼리에서 `GROUP BY HOST_ID`를 할 때 `SELECT ID, HOST_ID`처럼 불필요한 `ID` 컬럼을 함께 조회하여 단일 컬럼 비교 조건(`WHERE HOST_ID IN ...`)을 위반함.
  - 헤비 유저의 ID를 뽑는 목적에 맞춰 서브쿼리 `SELECT` 절에는 `SELECT HOST_ID` 단일 컬럼만 추출해야 함.
- **정렬 방향 확인**: "아이디 순으로 조회" 조건은 내림차순(`DESC`)이 아닌 기본 오름차순(`ASC` 또는 생략) 정렬 적용.

### [SQL 9일차 2번 - 오프라인/온라인 리얼타임 상품 판매 데이터 통합하기]
- **날짜 필터링 와일드카드와 `=` 혼용**: `WHERE DATE_FORMAT(SALES_DATE, "%Y-%m-%d") = '2022-03%'` 처럼 `=` 연산자에 `%`를 사용하면 0건 반환됨 -> `LIKE '2022-03%'` 또는 `DATE_FORMAT(SALES_DATE, '%Y-%m') = '2022-03'` 적용.
- **`OFFLINE_SALE` 테이블의 없는 컬럼 참조**: `OFFLINE_SALE` 테이블에는 `USER_ID` 컬럼이 없으므로 `SELECT USER_ID` 실행 시 Column Error 발생 -> `NULL AS USER_ID`로 더미 컬럼 지정 필수.
- **`ORDER BY` 구문 언더바 오타**: `PRODUCT_ID_ASC` 처럼 언더바 오타 작성 -> `PRODUCT_ID ASC` 띄어쓰기 구분.
- **날짜 출력 포맷팅 누락**: `SALES_DATE` 출력 시 시/분/초가 포함되지 않도록 `DATE_FORMAT(SALES_DATE, '%Y-%m-%d') AS SALES_DATE` 적용.

## 3. 핵심 배운 점 및 쿼리 패턴
1. **다중 행 서브쿼리 필터링 (`WHERE 컬럼 IN (서브쿼리)`)**: 특정 컬럼의 그룹 조건(`COUNT(*) >= 2`)을 만족하는 대상 목록을 서브쿼리로 추출한 뒤, 메인 쿼리 `WHERE HOST_ID IN (...)` 형태로 매칭.
2. **`UNION ALL` 테이블 통합 패턴**: 컬럼 구조가 다른 두 테이블을 합칠 때는 없는 컬럼을 `NULL AS 컬럼명`으로 명시하고 `DATE_FORMAT`으로 날짜 포맷을 일치시켜 병합.
